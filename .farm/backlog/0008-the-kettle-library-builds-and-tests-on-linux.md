- [ ] #8 The Kettle library builds and tests on Linux with plain Swift
      accept: on Linux (swift 6.1, no Xcode, no Apple SDK) `swift test` builds the Kettle target and runs KettleTests green; on macOS `swift test` builds and runs everything exactly as before (Kettle, KettleExperimental, both test targets, the default traits). Package.swift drops KettleExperimental, its product and KettleExperimentalTests when the manifest is evaluated on Linux (`#if os(Linux)` in the manifest), since that module is Objective-C (cloud_protocol.m, RecompSteamSession.m, RecompSteamAuth.m, RecompSteamConcurrentPlay.m) and links the Security framework. In Sources/Kettle: KettleClient.swift imports CryptoKit when it can and swift-crypto's Crypto otherwise (`#if canImport(CryptoKit)`, swift-crypto a dependency only `.when(platforms: [.linux])`), same API calls; UnlockGate.swift (StoreKit), AccountStore.swift (Security, the keychain) and WebAuthenticator.swift (AuthenticationServices, UIKit/AppKit) compile only where their framework exists (`#if canImport(StoreKit)` etc. around the whole file), and nothing on Linux refers to them; KettleClientTests.swift gets the same CryptoKit/Crypto switch, and any test of the Apple-only types sits behind the same canImport. README gains a "Platforms" line: the library on Apple platforms and Linux, the experimental module and the StoreKit, keychain and web sign-in parts on Apple platforms only. The gate (`.farm/project.yml` test: swift test) is unchanged.
      Why: the farm's v2 lanes run in Linux pods (ai-agents, the only machine of the v2 farm today); `swift test` there stopped at "no such module" on StoreKit, Security, AuthenticationServices and CryptoKit, so no item could pass the gate. The owner, 2026-11-02: "lets make kettle build on linux too".
      Decisions already made: Linux gets the library, not the experimental module (an Objective-C Steam client has no Linux story worth keeping); no Apple behaviour changes; no stubs that pretend the keychain or StoreKit exist on Linux — the types are simply absent there; swift-crypto pinned `from: "3.0.0"`.
      Must not touch: server/ (TypeScript, its own tests); the experimental module's sources; the traits.
